Every refusal comes with a short code (like no_lock_access) and a human message. The message is for you; the code is for searching this table, and for telling support exactly what you saw.

First, the number family

Each error also has a three-digit HTTP status. You rarely see it, but it tells you what kind of no it is:

400

Bad request: the app sent something odd.

401

Not signed in (or the sign-in expired).

403

Signed in, but not allowed.

404

Not found.

409

Conflict: not possible right now, in this state.

410

Gone: it existed, but is finished for good.

419 / 422

Session expired / some fields need fixing.

429 / 500

Too many tries, slow down / the server tripped.

The web's traffic light. 200s are green, 400s mean "you can't do that", 500s mean "oops, our fault".

Click a problem to open it. Each one lists the likely causes, most common first, and the fixes.

For everyone

{i:triangle-alert} The door says "State unknown" or "State stale"
Likely causes
  • The lock hasn't reported in for a while (weak Wi-Fi, low batteries).
  • The Eufy "Locked/Unlocked" notifications are off, so LockGuard never hears about changes.
Fixes
  1. Look at the door. Safety first.
  2. Tap Refresh.
  3. Tell your administrator if it keeps happening; they'll check batteries, Wi-Fi and the Eufy notifications.
{i:triangle-alert} "Device unavailable" or "Eufy connection degraded"
Likely causes
  • The lock is offline (batteries, Wi-Fi).
  • The bridge on the server stopped, or the Eufy cloud is having a bad day.
Fixes
  1. Use your physical key or keypad if you need to get in.
  2. Administrators: open System health and see which part is red.
  3. Restart the bridge (below) and check its window for errors.
npm run bridge
{i:triangle-alert} I can't see an Unlock button
Likely causes
  • Your role doesn't include unlocking (Security Administrator, Read-Only Auditor), or an administrator turned remote unlocking off for you with a Deny override.
  • You haven't been given access to that door, or your time window isn't open.
  • Commands are switched off for the lock.
Fixes
  1. Ask an administrator to check your role and overrides for Request unlocking and Request remote unlocking (how).
  2. Check your access times with whoever gave you access.
{i:triangle-alert} It asks me for a registration code

You're signing in on a device that isn't your registered one, or your browser forgot LockGuard (cleared data, private mode, different browser).

Fixes
  1. Use your registered phone, in the same browser as before.
  2. Or ask an administrator for a new registration code and type it in.
Private or incognito tabs throw away LockGuard's device cookie when closed, so you'd need a new code every time. Use a normal tab.
{i:triangle-alert} "Finish the LockGuard training" when I sign in

You were invited and haven't finished Pip's lessons and quiz yet (training_required). Open the invitation email and tap Accept Invitation; you'll continue where you left off. Link expired? Ask for a resend.

{i:triangle-alert} The invitation email never arrived
Fixes
  1. Check spam / junk / "Promotions".
  2. Administrator: look at the invitation in the list. A warning means sending failed; check Settings → Email settings, send a test email, then Resend.
  3. Gmail users: the password must be an App Password, not your normal one.
{i:triangle-alert} "This address cannot share your location"

Browsers only share location with https:// sites. Use the HTTPS address of LockGuard, and allow location when the browser asks (Settings → Safari/Chrome → Location if you said no before).

{i:triangle-alert} "Too many attempts. Wait a few minutes"

A safety brake after several wrong passwords, codes or registration codes. Wait the time shown (usually up to 15 minutes), then try carefully. Forgot your password? Use Forgot your password? on the sign-in page.

For administrators

{i:triangle-alert} Commands are refused: "Commands are turned off for this lock"

New locks start with commands off. Open Locks → the lock and turn Commands on (you'll confirm your password).

{i:triangle-alert} Commands say "Failed" or "Unknown result" all the time
Checklist
  1. Is the bridge running, and does its window show errors?
  2. Are LOCKGUARD_BRIDGE_SECRET values identical in both .env files?
  3. Is the queue worker running? Restart it after updates.
  4. Is EUFY_MQTT_BROKER_IP set? Commands sent through the wrong Eufy server are accepted and silently dropped. See docs\EUFY_BRIDGE.md.
  5. Lock Wi-Fi and batteries.
php artisan queue:restart php artisan queue:work --tries=1
{i:triangle-alert} The lock state is old or never updates
  1. Make sure the scheduler is running (it syncs every 5 minutes).
  2. In the Eufy app, turn on Locked and Unlocked notifications for the lock.
  3. Sync by hand:
php artisan lockguard:sync-locks
{i:triangle-alert} Nobody can sign in through the domain ("session expired" or 401)

The domain must be listed in SANCTUM_STATEFUL_DOMAINS, and the web app must be told its public host name. Update backend\.env, then clear the cached settings:

php artisan config:clear

Then restart the API and, for the web app, set the host before starting it:

$env:LOCKGUARD_PUBLIC_HOSTS = "lockguard.example.com" npx vite preview
{i:triangle-alert} I'm the only administrator and "You have not been given access to this lock"

Nobody can give themselves access through the website. Do it at the server:

php artisan lockguard:grant-lock-access you@example.com 1
{i:triangle-alert} The only Super Administrator is locked out

Create a second Super Administrator at the server, sign in as them, and fix the first account (reactivate, sign out everywhere, or issue a device code).

php artisan lockguard:create-admin --name="Backup Admin" --email=backup@example.com Always keep two Super Administrators. One is a single point of failure, and the rules stop people editing themselves.
{i:triangle-alert} "Something went wrong on the server"

Read the newest lines of the log for the real reason:

Get-Content storage\logs\laravel.log -Tail 60

Common causes: the database is down (start MySQL), a migration wasn't run after an update (php artisan migrate --force), or the disk is full.

{i:triangle-alert} How do I update LockGuard safely?
git pull cd backend; composer install --no-dev --optimize-autoloader; php artisan migrate --force; php artisan config:clear; cd .. cd frontend; npm ci; npm run build; cd .. cd integrations\eufy; npm ci; cd ..\..

Then restart all four windows (API, queue worker, scheduler, web app) and the bridge.

Before updating, back up MySQL. If something goes wrong, you can roll back instead of rebuilding by hand.
{i:triangle-alert} "Port already in use" when starting something

Something else is using that number. Find out what:

Get-NetTCPConnection -State Listen -LocalPort 8100,8788,4173 | Select-Object LocalPort, OwningProcess

Either stop the other program or move LockGuard's part to another port (e.g. BRIDGE_PORT and LOCKGUARD_BRIDGE_URL together).
