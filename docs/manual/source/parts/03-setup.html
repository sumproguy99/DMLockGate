This chapter takes you from an empty computer to a working LockGuard that people can reach from their phones. Every command has a Copy button. Run them in order.

The commands below use PowerShell on Windows (the prompt looks like PS>). On Linux or macOS, the same commands work in a normal terminal (prompt $); only the setup script in step 3.3 is Windows-specific.

3.1 What you need

A ready-made part. Like buying wheels instead of inventing the wheel. If LockGuard signs in with the same Eufy account as your phone, Eufy may sign your phone out. Create a second Eufy account, then in the Eufy app share the lock with it. In the Eufy app also turn on both the "Locked" and "Unlocked" notifications for each lock, or LockGuard will never hear that the door locked.

3.2 Get the code

Pick a folder (we'll use D:\lockguard) and download LockGuard into it:

git clone https://github.com/sumproguy99/DMLockGate.git D:\lockguard cd D:\lockguard

Then install the building blocks for each of the three parts:

cd backend; composer install --no-dev --optimize-autoloader; cd .. cd frontend; npm ci; cd .. cd integrations\eufy; npm ci; cd ..\.. The project has three folders that matter: backend (the brain, PHP), frontend (the screens, React) and integrations\eufy (the bridge, Node.js). Most problems are solved by running a command in the right folder.

3.3 Create the database

First create the settings file from the example, then run the database helper. It creates a lockguard database and user with a strong random password, and writes the connection details into backend\.env for you. It asks for your MySQL root password once and never stores it.

Copy-Item backend\.env.example backend\.env pwsh -File scripts\setup-mysql.ps1 If MySQL is installed somewhere unusual, tell the script where: -MySqlExe "C:\path\to\mysql.exe". Using an admin account other than root? Add -AdminUser yourname. It's safe to run again; it just rotates the password.

3.4 Configure the backend

Open backend\.env in a text editor (Notepad is fine). These are the settings you must look at. Lines starting with # are comments.

APP_NAME="DM LockGuard" APP_ENV=production APP_DEBUG=false APP_URL=https://lockguard.example.com # The address people use in their browser. Invitation links point here. LOCKGUARD_PUBLIC_URL=https://lockguard.example.com # Which addresses may sign in with cookies (add your domain). SANCTUM_STATEFUL_DOMAINS=lockguard.example.com,localhost,127.0.0.1 # How LockGuard talks to locks: unconfigured (sends nothing), fake (pretend lock), eufy_bridge (real) LOCKGUARD_LOCK_DRIVER=unconfigured # Unlocking away from the property: standard, step_up, location_required or disabled LOCKGUARD_REMOTE_UNLOCK_POLICY=step_up # One registered phone per person (recommended) LOCKGUARD_DEVICE_BINDING=true LOCKGUARD_DEVICE_BINDING_EXEMPT_ROLES=super_administrator,security_administrator

Now generate the app's secret key, build the database tables, and load the built-in roles and permissions:

php artisan key:generate php artisan migrate --seed --force Building instructions for the filing cabinet. "Migrate" means "build or update the drawers." Putting the first labelled folders into the new cabinet. The APP_KEY encrypts secrets such as two-step sign-in keys and the email password. If you lose it, those can't be decrypted. If someone else gets it, they could read them. Back up .env somewhere safe and never commit it to Git or share it in chat.

3.5 Create the first Super Administrator

The first account must be made at the server. Nobody can create it from the website, and that's on purpose.

php artisan lockguard:create-admin --name="Your Name" --email=you@example.com

It asks for a password twice (at least 12 characters, with letters and numbers). Typing doesn't show on screen. That's normal, not broken.

My password is "incorrect". That way, when I forget it, the computer reminds me: "Your password is incorrect."

3.6 Build the web app

npm run build

This turns the source code into fast, compact files in frontend\dist. Run it again every time you update LockGuard.

3.7 Connect your Eufy locks

Step A: configure the bridge. Create its settings file and fill it in:

Copy-Item .env.example .env notepad .env EUFY_USERNAME=lockguard-account@example.com EUFY_PASSWORD=the-second-accounts-password EUFY_COUNTRY=US # Shared secret: at least 32 random characters, the SAME value in backend\.env LOCKGUARD_BRIDGE_SECRET=paste-a-long-random-secret-here BRIDGE_HOST=127.0.0.1 BRIDGE_PORT=8788 # Where the bridge reports lock events (your API address) LOCKGUARD_EVENTS_URL=http://127.0.0.1:8100/api/internal/eufy/events

Make a good random secret with this one-liner and paste it in both files:

-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 48 | ForEach-Object {[char]$_})

Step B: tell the backend to use the bridge. In backend\.env:

LOCKGUARD_LOCK_DRIVER=eufy_bridge LOCKGUARD_BRIDGE_URL=http://127.0.0.1:8788 LOCKGUARD_BRIDGE_SECRET=the-same-long-random-secret

Step C: start the bridge (leave this window open):

npm run bridge

Step D: find and register your locks. First add a property (a building or home) in the web app under Properties, note its number (ID), then:

php artisan lockguard:sync-locks --register --property=1

New locks arrive with commands switched off, for safety. Open Locks, choose a lock, and turn Commands on when you're ready.

Step E: give yourself access. LockGuard never lets anyone change their own access from the website (so no one can quietly promote themselves). If you're the only administrator, do it at the server:

php artisan lockguard:grant-lock-access you@example.com 1 Add --until="2026-12-31 18:00" for access that ends on its own, or --revoke to remove it. Lock numbers (IDs) are shown on the Locks page.

3.8 Start the background workers

LockGuard has three jobs that must keep running. Each gets its own window (or Windows service):

JobCommandWhat it does
APIphp artisan serve --host=127.0.0.1 --port=8100Answers the app's questions.
Queue workerphp artisan queue:work --tries=1Delivers lock commands and emails in the background.
Schedulerphp artisan schedule:workEvery minute: expires stale commands and checks alerts. Every 5 minutes: syncs lock states. Daily: deletes old location data.
Web appnpx vite preview (in frontend)Serves the built screens on port 4173 and passes /api to the API.
# Window 1 php artisan serve --host=127.0.0.1 --port=8100 # Window 2 php artisan queue:work --tries=1 # Window 3 php artisan schedule:work # Window 4 npx vite preview The queue worker keeps the old code in memory. After you update LockGuard, stop it (Ctrl+C) and start it again, or lock commands may behave like the old version. Like apartment numbers in one building. The computer is the building; each program lives at its own number.

3.9 Set up email

Invitations are emails, so LockGuard needs an email account to send from. Sign in as Super Administrator and open Settings → Email settings.

  1. Click a provider button (Gmail, Outlook / Microsoft 365 or SendGrid) to fill in the technical bits.
  2. Enter the username (usually your full email address) and password. For Gmail, use an App Password: Google Account → Security → 2-Step Verification → App passwords. Your normal Gmail password won't work.
  3. Enter the "From" address and name people will see, e.g. DM LockGuard.
  4. Tick "Send email through this server" and click Save. LockGuard asks for your password again to confirm it's you.
  5. Click "Send test email" and check your inbox (and spam folder).
The email password is stored encrypted and is never shown again, not even to you. To change it, type a new one. To keep it, leave the box empty. The post office counter for email. LockGuard walks up, hands over the letter, and the mail server delivers it.

3.10 Put it online (HTTPS)

To use LockGuard from phones outside your network, point a domain name at your server and put a reverse proxy with a free HTTPS certificate in front of port 4173. (The original installation uses Nginx Proxy Manager with Let's Encrypt.)

  1. DNS: create a record for lockguard.example.com pointing at your server's public address.
  2. Proxy: forward https://lockguard.example.com to http://127.0.0.1:4173, with a Let's Encrypt certificate and "Force SSL" on.
  3. Tell LockGuard its name: set LOCKGUARD_PUBLIC_URL and add the domain to SANCTUM_STATEFUL_DOMAINS in backend\.env. For the web app, set LOCKGUARD_PUBLIC_HOSTS=lockguard.example.com before running npx vite preview.
  4. Trust the proxy: list its address in LOCKGUARD_TRUSTED_PROXIES so LockGuard sees visitors' real addresses.
The padlock in your browser bar. It means nobody in between can read or change what you send, and you're really talking to your server. Only the web app (port 4173, through the proxy) should face the internet. Keep the API (8100) and especially the bridge (8788) on 127.0.0.1. The bridge can move real locks.

3.12 Settings reference

All in backend\.env. Change one, then restart the API and queue worker.

LOCKGUARD_LOCK_DRIVERunconfiguredHow commands reach locks. unconfigured sends nothing (safe default), fake is a pretend lock for testing, eufy_bridge is real.
LOCKGUARD_REMOTE_UNLOCK_POLICYstep_upRemote unlocking: standard, step_up (re-enter password), location_required, or disabled.
LOCKGUARD_STEP_UP_SECONDS600How long a "confirm it's you" check lasts (10 minutes).
